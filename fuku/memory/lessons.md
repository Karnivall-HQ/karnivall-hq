- 2026-11-05 · [orientation] With no missions set, a read-only scan of connected accounts produced concrete, numbers-backed mission proposals. **Rule:** when idle, look at real data from the connectors before writing generic research.
- 2026-11-05 · [env] The network is now Full (fbcdn.net and fabwarehouses.com are reachable from the cloud). **Rule:** if a site fails DNS again, note it under "Needs a local session" and don't retry other sites in the same run.
- 2026-11-05 · [learning] Big doc sets: pdftotext → split across 3 parallel readers with a strict STATED/INFERRED/not-addressed template → spot-check key quotes → synthesize myself against real account data. **Rule:** reuse this for any knowledge upload.
- 2026-11-15 · [meta-models] The 07:00 models (gate, criterion 1) hard-code the old Rp 300k/day budget; an overnight 10× budget change made both outputs meaningless while still printing clean numbers. → **Rule:** read the activity log before running any model; a budget/bid/status change since the last run voids the model until it is re-based (tracker routine step 0).
- 2026-11-15 · [meta-models] Blend table for the 3M change: with BC fixed, raising PEIKIRA spend from Rp 300k to 3M/day moves the 7d account CPL by < 7k at any PEIKIRA CPL; the PEIKIRA CPL itself decides criterion 1. And a bid cap above target (105k > 95k) can't deliver the target even when it binds. → **Rule:** for any budget change, judge on the engine's CPL vs target, not on spend; check cap ≥ target before treating a cap as a CPL guard.
- 2026-11-15 · [meta-models] Re-basing a model on a CBO budget change: the 3M CBO paced only ~475k/day under a 105k cap, and at today's CPL more spend *raises* the 7d blend (BC's cheap leads shrink in the mix: break-even 101.1k → 96.7k at Rp 1M/day *(calc)*). → **Rule:** re-base models on actual daily spend (`--budget`), never on the CBO setting.
- 2026-11-15 · [process] Renumbering OUTBOX asks (old #1/#2 → #2/#3 at 07:05) left stale "OUTBOX #1a/#1b", "asks #1 + #2" and "OUTBOX #3" (photos, now parked) in the pre-written 11/16 skeleton; the Monday run would have pointed Alvian at the wrong asks. → **Rule:** whenever OUTBOX asks are renumbered or parked, grep `OUTBOX #` across `fab_advertising/reports/` pre-staged files and fix them in the same run.
- 2026-11-15 · [process] The sweep after the 07:05 renumber found 5 more staged files (11/20 gate brief, gate-miss note, readout template, S1 card, 12/05 path) with asks numbered two renumbers ago (gate brief still called W1+W2 "#1" and photos "#2"). → **Rule:** in staged files, name an ask by content plus number ("ask #2 (pause Ad015)"), so a stale number is visibly wrong instead of silently wrong.
- 2026-11-15 · [meta-diagnosis] ADSET-3 sat at 0 impressions for 3 days with no errors; the cause was not only CBO allocation: its targeting is identical to sibling PEIKIRA2, so Meta enters the sibling (with conversion history) in shared auctions, and a bid cap blocks a 0-history ad set further. → **Rule:** for a starved new ad set, compare its targeting with sibling ad sets before blaming CBO; on full overlap only a min spend (or a separate campaign) forces delivery, and freeing budget elsewhere does not.
- 2026-11-15 · [process] The parked "are the 15 images the shoot?" ask sat for Alvian, but viewing the images (read-only `ads_get_ad_images` + download) answered it in one run: facility photos + graphics, not the shoot. → **Rule:** before asking Alvian what an asset *is*, look at it; only ask what can't be seen (e.g. "is the site open?").
- 2026-11-15 · [meta-creative] The ADSET-3 read card left one ad "map at read time"; mapping it now (3 read-only calls) showed it was the most important ad in the set (AKIRA-016 = the account's best-history look, home clutter + stickers), which changed what the starvation costs. → **Rule:** when a card has an unmapped row, map it the same day; "later" rows hide the one that matters.
- 2026-11-15 · [meta-tests] The 11/27 verdict table had "UNDER-TESTED = spend < 4 × target"; a 4-lead win at target always costs ≤ that, so 333 of 408 overlap cells were WINNER+UNDER-TESTED with opposite asks. → **Rule:** a minimum-spend "too early" bucket overlaps every success bucket; check kill rules, then success, then sample size, and write that order into the table.
- **2026-11-15 22:01 · Pull `old_value` when drafting an undo, not later.** Meta's log labels ("Automatically bid for impressions/clicks/actions") need translating into Ads Manager terms ("Highest volume") before they go into a change list; doing it early leaves room to flag the INFERRED part. Rule: an undo change list names the exact pre-change state from the log, in the words Markus sees on screen.
- 2026-11-16 · [meta-models] The criterion-1 script re-based on the 11/15 spend (Rp 153.6k/day) printed a *better* CPL outlook (LWD 11/28 → 12/02) because less PEIKIRA spend means more of BC's cheap leads in the blend, while the same cap makes the Rp 1M/day half of the criterion unreachable. → **Rule:** for a two-part criterion, report both halves on every model run; a CPL-only model must say what spend/day it assumes next to its date.
- 2026-11-16 · [process] Pre-staged send-ready messages (11/20 gate-miss note, criterion-2 line) quietly carried the old Rp 300k/day base and a "5 budget steps" sentence for 2 days after the budget went to Rp 3M + cap; they would have gone out wrong on 11/20. **Rule: the run after any structural account change (budget, cap, bid strategy, objective), grep every pre-staged card/template for the old value and add a dated refresh block that overrides it.**
- 2026-11-16 · [meta-tests] A budget step is only a lever when the budget binds. Under a bid cap, spend is set by the cap (11/15: 5.1% of 3M; BC 11/05: 1.4% of 5M), so "+25% budget" is cosmetic. Rule: before any budget proposal, check 3-day spend ÷ budget; < 90% → no budget ask, name the real limiter (cap or creatives).
- 2026-11-16 · [meta-models] After the 11/15 00:41 change, the day's Rp 153.6k (and the 13:02 "265k/day" projection) was almost all a pre-cap-learning overnight burst (Rp 138k by 07:05); the steady capped pace was ~Rp 15–21k/day, a near-stop that the "5% of budget / half the old pace" lines hid for 30h. **Rule:** after any bid/budget change, split the first day at the change-time burst and project pace only from the post-burst hours; quote the post-burst rate in the status line.
