# Lessons

> **Retro 2026-11-06:** 13 meta-ads, creative, and site lessons were merged into `playbooks/meta-cpl-diagnosis.md`. The ones below aren't covered by a playbook.

- 2026-11-05 · [orientation] With no missions set, a read-only scan of connected accounts produced concrete, numbers-backed mission proposals. **Rule:** when idle, look at real data from the connectors before writing generic research.
- 2026-11-05 · [cloud] Cloud routines CAN push straight to `main` of alvianlim/karnivall-hq. **Rule:** always pull before editing, or local and cloud edits to NOW.md will conflict.
- 2026-11-05 · [env] The network is now Full (fbcdn.net and fabwarehouses.com are reachable from the cloud). **Rule:** if a site fails DNS again, note it under "Needs a local session" and don't retry other sites in the same run.
- 2026-11-05 · [learning] Big doc sets: pdftotext → split across 3 parallel readers with a strict STATED/INFERRED/not-addressed template → spot-check key quotes → synthesize myself against real account data. **Rule:** reuse this for any knowledge upload.
- 2026-11-06 · [process] In ~36h, 0 of 5 ad proposals and 0 of 4 site fixes were applied, while 7d CPL drifted 113k → 125k. Long multi-item decision packs stall. **Rule:** when proposals sit > 24h, re-ask with the single highest-impact item as a 1-line yes/no; don't add new packs on top.
- 2026-11-06 · [creative] Fab's #1 ad (Image087, ~Rp 90.8k CPL) shows the customer's *problem* (cluttered room at home), not the warehouse. I'd assumed the shoot needed the facility, which made the ask heavier than it had to be. → **Rule:** view the top winner at full size *before* briefing a shoot. Copy its subject, not just its style, and size the ask to what the winner actually needed.
- 2026-11-06 · [analysis] With 1–5 leads per side, a creative test can be read any way you like after the fact. → **Rule:** write the decision rules (spend-per-lead thresholds, min leads) into the pre-stage doc *before* the read date, then apply them as written.
- 2026-11-06 · [analysis] I'd framed the Fab CPL rise as a post-click leak, but the wk/wk pixel funnel shows post-click *improved* (VC→Lead 3.0% → 3.8%) while CPL rose. → **Rule:** before blaming a stage for a trend, compare that stage week-over-week, not just its absolute level.
- 2026-11-06 · [analysis] At 14:02 I called the Fab CPL rise "upstream" from account totals (CPM +16%). The campaign split showed every PEIKIRA metric improved; account CPM rose only because spend moved from cheap-CPM BC to PEIKIRA, and BC lost 10 leads/week. → **Rule:** never read a trend from account totals when 2+ campaigns spend; split by campaign first to rule out a mix shift.
- 2026-11-06 · [meta] Adding a 2nd ad set to a fixed-budget (CBO/campaign-budget) campaign let the new, worse ad set take 78% of spend on day 2, starving the proven one (Rp 78.6k CPL). → **Rule:** when a new ad set launches inside a shared budget, check its spend *share* daily, not just its CPL; a pre-set pause threshold can trip days before the planned read date.
- 2026-11-07 · [meta] PEIKIRA2 tripped my ≤1-lead pause rule at 20:02, then logged a 2nd lead by morning, so the ask would have been wrong if fired intraday. → **Rule:** evaluate lead-count thresholds on full-day data (first readout after 07:00), never on an intraday snapshot.
- 2026-11-07 · [process] Item 1 sat 48h in OUTBOX with zero response, even after being shrunk to one line. Hourly runs only wrote to the repo and never sent a push. → **Rule:** when a [DECISION] is re-asked, also send one push notification; never more than one push per ask per day.
- 2026-11-08 · [meta-ads] The PEIKIRA2 pause rule (≤ 1 lead) was disarmed by one overnight lead on 11/07, then the ad set burned another Rp 202k for 0 leads. → **Rule:** write test pause rules as a spend multiple of target CPL (e.g. ≥ 5× target with ≤ 2 leads), not a bare lead count; one lead is noise.
- 2026-11-09 · [analysis] PEIKIRA2 had its best day (2 leads on 11/08) right as the pause ask aged, which would have disarmed a lead-count rule again. The pre-set "either way" rule (campaign CPL vs control alone: 119k vs 75k) still held, so the ask stands. → **Rule:** every test pre-stage needs one *comparative* rule (split vs control) next to the absolute thresholds; it survives single good days.
- 2026-11-09 · [process] Two cloud runs in a row started on a shallow clone whose local `main` diverged from origin, so `pull --ff-only` failed. → **Rule:** on a failed ff-pull, `git fetch --unshallow origin main`, check `origin/main..main` is already-merged history, then align to origin; never push the stale history.
- 2026-11-09 · [meta-ads] The activity log showed "Updated status of ad after it finishes Ad Review: Active → Inactive", which reads like a Meta rejection, but the entity `status` was PAUSED: a human paused it through the MCP app. → **Rule:** before labeling an Inactive event as a system or review action, read the entity's `status` (PAUSED = human) and its parent's status (a paused ad ≠ a paused ad set).

- **2026-11-10 · Read where the money went before re-asking.** Markus paused only the top ad (006), not the ad set I asked about, and that alone moved spend back to the control (12–33% → 67%). Rule: when the team applies a partial version of an ask, measure the spend flow at the next readout and drop or shrink the ask if the effect landed, rather than repeating the original.
- 2026-11-10 · [process] From 11/07 on, 52 of 93 runs only re-checked the activity log and appended "nothing changed" to NOW.md, while M-001's second criterion (scale to Rp 1M/day) had no groundwork at all, and OUTBOX grew to 18 open items. → **Rule:** waiting on Alvian for one lever is not "blocked": work the mission's other criteria from the groundwork backlog, and keep "Needs you" to ≤ 3 lines so the live ask is visible.
- 2026-11-10 · [meta-ads] For "can this account scale to X/day?", the account's own history already held the answer: one week at Rp 919k/day (10/12–10/18) on the same creatives cost Rp 201k/lead, 2× the normal CPL. → **Rule:** before modelling a scale ladder, pull ≥ 8 weeks of weekly campaign spend + CPL and find the highest spend level each engine ever held at target CPL; that is its capacity, and the gap above it is a creative problem, not a budget one.
- 2026-11-10 · [meta-ads] I expected the Ad015 fallback to be "the next-best ad", but every other ad in the control ad set together did Rp 182k/lead (1.9× Ad015) on 1–2 leads each: CBO had starved them, so none is proven. → **Rule:** when one ad carries > 80% of an ad set's spend, treat the ad set as having no backup; the hedge is new creative, and contingency triggers (CTR/CPL/freq) must be written down before fatigue shows.
- 2026-11-10 · [research] The Ad Library MCP returns only page, headline and dates (no body/image), and snapshot pages need a login, so it can't show competitor hooks alone; the competitor's own site gave the useful facts (price ladder, deposit, self-move). → **Rule:** for competitor scans, use the Ad Library to find *who* advertises and how often they refresh, then read their website for offer/price; also scan our own page's results there for stale claims (found 8 live "Rp800.000" ads).
- 2026-11-10 · [copy] My first draft of the competitor price-objection reply claimed "the total comes out about the same once you add a truck + deposit", with no truck price checked and ignoring that deposits are refundable. **Rule:** in comparison copy, claim only differences that are checked (features and policies); a cost-parity claim needs both numbers in hand, otherwise describe the effort saved.
- 2026-11-10 · [meta-ads] The Ad Library suggested "≥ 8 old 800rb ads"; the in-account creative read showed **all 59** BC ads say 800rb while all PEIKIRA ads say 750rb, so the inconsistency is campaign-wide, not a stray batch. → **Rule:** for any copy-consistency question, join `ads_get_ad_entities` (spend > 0, creative_id) with `ads_get_creatives` body/title and size it by spend share before proposing pauses; a library sample undercounts.
- 2026-11-10 · [meta-ads] Before writing the Incess cap-raise proposal I assumed "spend is low because the cap is low"; the 8-week series showed spend swing −30% with **no** bid edits (activity log, category=bid) and flat CPL, so volume at a fixed cap is auction-driven and the base week matters. → **Rule:** for any bid-cap proposal, pull ≥ 8 weekly rows + the bid-category activity log, raise only ad sets with CPL ÷ cap < ~0.85, and pre-set a comparative rule (raised vs untouched ad sets, same week) so an auction swing isn't credited to the cap.
- 2026-11-11 · [meta-ads] I planned to re-raise "remove IG Stories" (based on 11/05 30d data) as the single ad ask; the fresh 7d split showed Stories at Rp 119k/lead, Feed at 166k, Reels at 48k, and cutting Stories would have left CPL flat. → **Rule:** before re-raising any parked placement or structure ask, re-pull the same breakdown on the latest 7d window and recompute the "CPL without it"; if the gain is gone, retire the ask in OUTBOX rather than send stale numbers.
