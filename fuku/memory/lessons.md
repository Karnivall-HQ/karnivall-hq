- 2026-11-05 · [orientation] With no missions set, a read-only scan of connected accounts produced concrete, numbers-backed mission proposals. **Rule:** when idle, look at real data from the connectors before writing generic research.
- 2026-11-05 · [env] The network is now Full (fbcdn.net and fabwarehouses.com are reachable from the cloud). **Rule:** if a site fails DNS again, note it under "Needs a local session" and don't retry other sites in the same run.
- 2026-11-05 · [learning] Big doc sets: pdftotext → split across 3 parallel readers with a strict STATED/INFERRED/not-addressed template → spot-check key quotes → synthesize myself against real account data. **Rule:** reuse this for any knowledge upload.
- 2026-11-16 · [read rules] A 3-day read card's CPL thresholds silently assumed enough spend to read a CPL; at ~Rp 180k a single extra lead flipped "undo" to "no ask". **Rule:** every read card needs a readability floor (spend < 3 × baseline CPL → judge volume only) and an explicit L = 0 row; dry-run every L, not just the likely one.
- 2026-11-16 · [branches] A pre-staged branch named "revert" pointed to a pack whose own trigger excluded that case (caps kept vs removed): the label and the target's entry condition had drifted apart after the rec changed. **Rule:** when a branch routes to another file, copy the target's entry condition into the branch label, and re-check every branch label the run a recommendation changes.
- 2026-11-16 · [plans] A scale plan under a bid cap used "cap steps after a verified winner", but the cap itself stops any new ad from reaching verdict spend: a circular gate. **Rule:** for every step trigger in a plan, check the current constraint lets the trigger be met (verdict spend ≤ capped pace × days × share); if not, the plan is void until the constraint lifts.
- 2026-11-18 · [pre-staging] The 11/27 template read the activity log only from 11/20, so a change applied between pre-staging and the 11/20 readout (undo, min spend) would read as "never". **Rule:** chained templates hand off a dated state snapshot (every setting the next card branches on), written by the upstream card; the downstream log window starts at that snapshot.
- 2026-11-20 · [models] For 5 days I pushed "undo the caps" and pre-staged "G1 ✅ not reachable", yet the gate passed (92.1k): starving the expensive leg (PEIKIRA ≈ 160–199k) lowered blended CPL by mix, so the undo helped criterion 2 (volume) but hurt criterion 1 (CPL). I'd only modelled the undo on volume. **Rule:** before pushing any structural ask, model its effect on *each* mission criterion separately and state the trade in the ask; when the cheaper leg (here BC) carries the blend, test "throttle the expensive leg + scale the cheap one" as an option.
- 2026-11-20 · [tests] The parked BC204-only cap probe could never be read: at Rp 2k/day even 5× delivery misses the Rp 190k kill floor inside 7 days, and its recent weeks went 0 leads. Re-running the 8-week ratio across all top ad sets found 4 that pass (33 leads pooled). **Rule:** size a probe so the group's projected 7d spend reaches its own kill/verdict floor; if one object can't, pool every object that passes the same gate and read the group with one comparative rule.
- 2026-11-20 · [planning] The 11/16 criterion-2 plan said "re-plan the day the caps come off", then on 11/20 I parked the undo myself, so that trigger could never fire and criterion 2 sat unplanned. → **Rule:** when I park or drop an ask, grep for any plan whose trigger depends on that ask, and write its "ask never happens" branch in the same run.
- 2026-11-20 · [creative] The ladder ad sets were tagged "Manny", "UGC", "Anak Tele" in my notes, but each runs on one ad (others ≈ Rp 0), and two "concepts" turned out to be the same real-facility angle; the one that breaks R11 (a staged parents scene) has the best CTR and the worst CPL of the four. **Rule:** before briefing "more of what works", list the carrying ad per ad set and look at its image + overlay text; group by angle, not by ad-set name, and judge CTR and CPL separately.
- 2026-11-20 · [creative] For a week the BC waves read as "blocked on a photo shoot", but N2's five images were already in the account (BC208 + 204F hashes via `ads_get_creatives`), so the ad is buildable today with zero new assets. **Rule:** before blocking a creative on new photos, pull the image hashes of the account's best live ads and build from those first; ask for a shoot only for an angle no existing image covers.
