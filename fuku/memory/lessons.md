# Lessons

> Format: `- YYYY-MM-DD · [area] What happened → **Rule:** what I'll do differently.`
> Consolidated into playbooks during retros. Keep this file under ~100 lines; prune what's been absorbed.

- 2026-11-05 · [meta-ads] Account-level scan of 20 accounts via Rudi MCP worked well with `level=ad_account`, `include_additional_context=false`, and the default fields (spend only). Industry benchmark often returns no data or "unavailable". **Rule:** scan spend first, then deep-dive only the accounts that are spending. Don't block on benchmarks.
- 2026-11-05 · [orientation] With no missions set, a read-only scan of connected accounts produced concrete, numbers-backed mission proposals. **Rule:** when idle, look at real data from the connectors before writing generic research.
- 2026-11-05 · Cloud routines CAN push straight to `main` of alvianlim/karnivall-hq. Rule: before you edit locally, pull first (the session hook does this), or local and cloud edits to NOW.md will conflict.
- 2026-11-05 · [meta-ads] Before diagnosing CPL/delivery, the budget activity log (`event_category=budget`) showed a teammate's 5M→300k budget cut that explained the delivery drop. **Rule:** pull activity logs first in any diagnosis; never attribute a change to performance until you've ruled out human edits.
- 2026-11-05 · [meta-ads] Bid-cap campaigns can show a huge daily budget while spending ~1%: the cap, not the budget, limits delivery. **Rule:** for under-spend, check `bid_strategy`/`bid_amount` before suggesting budget changes.
- 2026-11-05 · [creative] Pulling `ads_get_creatives` (body/title) for the top-spend ads told me what the business actually is (Fab Self-storage, price, location) faster than any question to Alvian. **Rule:** before writing new ad copy, read the live winners' and losers' copy and draft only from facts already in live ads; flag new claims for confirmation.
- 2026-11-05 · [meta-ads] An activity-log pull with limit 100 overflowed the tool output and had to be parsed from the saved file. The actor name "Rudi MCP" is the *app*, not a person: other people's AI sessions show up under the same name as mine. **Rule:** pull activity logs in ≤ 40-entry pages or by category, summarize them with python, and attribute changes by actor_id, never by app name.
- 2026-11-05 · [cloud] The cloud network blocks arbitrary sites (fabwarehouses.com failed DNS). **Rule:** any web-page audit goes to "Needs a local session" unless the domain has been allowlisted. Don't retry other sites in the same run.
- 2026-11-05 · [meta-ads] Activity-log "Ad delivered" events put the **ad set** ID in `extra_data.campaign_id`; looking it up as a campaign returns "not campaign entities". **Rule:** cross-check unknown IDs against the tracker / ad-set level before calling something a new campaign.
- 2026-11-05 · [meta-ads] A `publisher_platform` + `platform_position` breakdown at campaign level found the biggest waste (IG Stories, WA Status, Threads) faster than ad-level data. Absurd ad-set frequency (100–1,000) + CPM < Rp 1k = WhatsApp Status junk delivery. Ad-level 30d output overflows the tool limit; parse the saved file with jq. **Rule:** run the placement breakdown first on every CPL diagnosis.
- 2026-11-05 · [env] Ad images live on *.fbcdn.net. They were blocked until Alvian set Network access = Full, which took effect in the running session immediately. Creative `image_url` = full size; `thumbnail_url` = 64×64 only (useless for analysis). **Rule:** to see a creative, get creative_id from the ad → ads_get_creatives image_url → curl to scratchpad → Read.
- 2026-11-05 · [creative] For Fab (self-storage, Jakarta), authentic phone photos of the real warehouse beat polished/AI-rendered designs by 3–10× on CPL (n is small per ad, but the pattern holds across 13 ads). **Rule:** never brief AI renders or stock lifestyle scenes for Fab; brief real phone shoots with story-style stickers + price on the image. To view creatives: ad → creative_id → ads_get_ad_images(hashes) `url` → curl → PIL contact sheet → Read.
- 2026-11-05 · [meta-ads] Before blaming attribution, read ad set `targeting`: in Fab, every ad set was broad Jakarta + Advantage+, no custom audiences or exclusions → there was no remarketing layer. Weekly time_increment=7 campaign data gives a cheap natural experiment for halo effects. **Rule:** test funnel/halo theories with targeting reads + week-by-week blended CPL before restructuring.
- 2026-11-05 · [learning] Big doc sets: pdftotext → split across 3 parallel readers with a strict STATED/INFERRED/not-addressed template → spot-check key quotes → synthesize myself against real account data. It took ~2 min of reading for 57k words. **Rule:** reuse this for any knowledge upload.
- 2026-11-06 · [meta-ads] `ads_get_dataset_stats` on the pixel gives a free post-click funnel (ViewContent → Form → Lead) without touching the site. `event_total_counts` returns browser and server rows separately (sum them, ~÷2 for uniques); `url` aggregation strips paths (useless per page); `start_time` is Unix seconds and must be ≤ 28 days old (compute it with `date -d … +%s`, don't guess). **Rule:** start every CVR/landing-page question with the pixel funnel, then curl the pages for copy contradictions.
- 2026-11-06 · [creative/site] Fab's WordPress pages are cloned between locations, and the leftover copy ("Kelapa Gading", "Jakarta Pusat") contradicts the ad. **Rule:** when auditing a landing page, grep every page in the flow for location and price strings and compare them with the live ad copy.
- 2026-11-06 · [meta-ads] "Winner" labels from 30d data went stale: Manny5 (4 leads/30d) spent only Rp 18k / 0 leads in the last 7d, and the "broken" ad 201B had spent Rp 0 for 14d, so its issue cost nothing. **Rule:** before flagging an ad issue as urgent, check that ad's recent spend (14d). Re-check "winner" lists against 7d delivery before putting them in a proposal.
