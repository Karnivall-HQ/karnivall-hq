- 2026-11-05 · [orientation] With no missions set, a read-only scan of connected accounts produced concrete, numbers-backed mission proposals. **Rule:** when idle, look at real data from the connectors before writing generic research.
- 2026-11-05 · [env] The network is now Full (fbcdn.net and fabwarehouses.com are reachable from the cloud). **Rule:** if a site fails DNS again, note it under "Needs a local session" and don't retry other sites in the same run.
- 2026-11-05 · [learning] Big doc sets: pdftotext → split across 3 parallel readers with a strict STATED/INFERRED/not-addressed template → spot-check key quotes → synthesize myself against real account data. **Rule:** reuse this for any knowledge upload.
- 2026-11-07 · [process] Item 1 sat 48h in OUTBOX with zero response, even after being shrunk to one line. Hourly runs only wrote to the repo and never sent a push. → **Rule:** when a [DECISION] is re-asked, also send one push notification; never more than one push per ask per day.
- 2026-11-11 · [site] grep counts on a page overstate edit work: "Rp 800.000 ×3" was 1 FAQ answer + its schema copies; "Kelapa Gading ×2" was one footer address. **Rule:** map every hit to its visible line (strip script/style, count find strings) before telling anyone "×N fixes", and hand them exact find → replace strings.
- 2026-11-12 · [ads] Item 4 was built on a 30-day CPL ÷ cap ratio (0.889). The 8-week read (playbook §C) came out at 1.02, which kills it. Re-validating each 11/05 item on fresh data retired all five in 2 days. **Rule:** a bid-cap or scale proposal is never written on < 8 weekly rows; the first version of a diagnosis proposal is a hypothesis until re-pulled on the full window.
- 2026-11-12 · [site/copy] My W2 replacement text imported the ads' "kode FAB750" into a site that never mentions a code (0 hits; it says "Harga Promo Launching" 12×). Number-only checks missed it. **Rule:** before handing over any site or ad copy edit, count the target page's own phrases for the claim (price word, code, location) and reuse them; never add a claim the page doesn't already make.
- 2026-11-12 · [tools] An ad-set pull with `filtering` on amount_spent + `time_increment 7` returned real weeks for only the first ad set and zeros for the rest. Re-pulling by `object_ids` gave the true rows. **Rule:** for multi-week ad-set history, pull by `object_ids`; distrust a time-series where a known-spending entity shows 0.
- 2026-11-12 · [site/copy] My WA script quoted unit sizes 4.75/9.5/19 m³ from the 11/06 audit; the page every ad lands on says 3.8/7.6/15.2 and puts "kasur" only in Medium. A draft had carried a stale, wrong fact for 6 days. **Rule:** every number or capacity claim in a draft (sizes, prices, what fits) is re-read from the ad landing page at handover time, not copied from an older report.
- 2026-11-12 · [creative] Checking only an ad's product claims against the landing page missed that two new angles (online sellers, renovation) have zero support for the *situation* itself on the page. → **Rule:** before drafting a new-audience ad, grep the landing page for the audience/situation words too; if 0, flag message-match risk and rank that ad last in its wave.
- 2026-11-12 · [process] The ad-copy-vs-landing-page check ran 4× today and each time caught a new overclaim type (vocabulary, stale numbers, unsupported situation, implied 'only'/count words). **Rule:** follow `playbooks/ad-copy-page-check.md` before calling any copy paste-ready.
- 2026-11-12 · [build spec] Five build sheets copied Ad015's text but never its creative settings; a read-only creative pull showed Advantage+ text translation + cv_transformation switched on, which can alter sticker copy and the raw-photo look under test. **Rule:** before a build spec is apply-ready, read the reference ad's creative settings (CTA, IG account, Advantage+ enhancements) and state which to copy and which to turn off.
- 2026-11-13 · [team] Markus + a new actor launched a 6-ad photo wave (ADSET-3) overnight without any of Fuku's build sheets, after 3 days of unanswered photo asks. → **Rule:** when the activity log shows a new ad set, write its read card (kill + comparative + verdict) the same run and check its copy against the landing page; then re-frame open asks around what the team actually shipped instead of repeating the old ask.
- 2026-11-13 · [tools] `ads_get_creatives` returned an empty `body` for 5 of 6 multi-image (flexible) creatives, so the 07:02 card only checked one ad's copy. The `preview_url` from `ads_get_ad_preview`, curled, holds `"textData":{"primaryText":…}` with the real text. **Rule:** when `body` is empty, curl the preview URL and parse `textData` before saying an ad's copy is checked; the destination URL is not in either, so label it INFERRED.
- 2026-11-13 · [modelling] The 11/11 gate brief said a new ad set had to win at ≤ 70k to open the gate; the 11/13 refresh with the right incumbent CPL (116k) gives ≤ 83.5k at a 1/3 share. The bar depends on what the new spend displaces, not on the target alone. **Rule:** for any new ad set inside a CBO, compute its break-even CPL against the CPL of the ad sets it takes spend from, at 2–3 share levels, and put that number in its read card.
- 2026-11-13 · [ads/modelling] A new ad set's break-even CPL depends on its share AND how many days it delivers in the window; each zero-impression day cut the 1/3-share bar ~4–6k. → **Rule:** state break-evens as a share × start-day table, not one number, and re-read it the day delivery actually starts.
- 2026-11-13 · [ads/CBO] The team's new ADSET-3 sat at 0 impressions for 9h inside the PEIKIRA CBO with no errors and approved ads, while the two ad sets with conversion history took all spend. → **Rule:** for a new ad set in a CBO, check delivery at the first poll after launch; 0 impressions + no errors = starvation, so pre-write the min-spend fix with its removal rule and ask only if it persists to the next poll.
- 2026-11-13 · [rules] Two pre-set rules written the same day (pause if 3-wk > 105k / keep if week ≤ 50k) both fire at one lead count (2 more leads on Incess 019 Copy 5). → **Rule:** when pre-staging a read, tabulate outcomes by result count and check every rule pair for overlap; settle precedence in writing before the data lands.
- 2026-11-13 · [planning] The criterion-2 re-plan carried ADSET-3's fix (ad-set minimum daily spend) into future waves, but the build sheets add waves as ads inside the control ad set, where an ad-set setting can't help. Caught only when writing the W5–6 sheet. → **Rule:** when reusing a fix from one case in a plan, check the object level matches (campaign / ad set / ad) before writing it in; link to the rule that already covers that level.
- 2026-11-13 · [planning] The wave plan put "pick W2 rows at W1 day-7" on the same day as W2 launch, so W2 photos could never be shot after the pick; only seen when laying the plan out as a dated per-person calendar. → **Rule:** for any plan that depends on another person delivering inputs, lay it out as dates × who × what; a decision on the same day as the input it selects is a gap: front-load those inputs.
- 2026-11-14 · [ads/diagnosis] Ad015's 7d CPL jumped 114.5k → 166.1k while its CTR rose 1.4% → 2.3%; a CTR-based fatigue rule alone would never have fired. → **Rule:** when CPL rises with flat or rising CTR, read it as a post-click problem (page / offer mismatch), not creative fatigue, and say so in the ask; pair the ad fix with the page fix.
- 2026-11-14 · [modelling] The 11/13 gate brief said the site fix alone opened the gate; one 0-lead day inside the window plus the incumbent ad sets sliding 116k → 144k turned that into "no single lever works". A scenario table goes stale in one day once the judged window has started. **Rule:** once a gate window is open, lock the known days as actuals and re-run the scenarios on each daily readout, not on quiet runs later; sanity-check every lever moves CPL in the expected direction before writing numbers.
- 2026-11-14 · [planning] For 2 days my notes treated the likely 11/20 gate miss as "M-001 at risk" overall, but the gate only feeds criterion 2; criterion 1 is judged on a fresh window (11/28–12/04) that the open asks can still win (≈ 88k if live by 11/27). → **Rule:** when an intermediate gate looks lost, model each success criterion on its own judged window and state its last workable date before writing any miss message.
